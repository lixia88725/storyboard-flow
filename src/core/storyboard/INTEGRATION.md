# Storyboard wave-1 integration map (not wired)

`index.ts` exports `applyStoryboardEdit`, `createProjectHistory({ maxEntries })` and `precedingActiveImages`. Both future views must read the **same** `ProjectHistoryV1.current()` snapshot. `ResultV1` failures must be surfaced without publishing a project, performing file effects or recording an undo entry. The standalone core is synchronous and has no React, DOM, filesystem or brush dependency. `ChangeSetV1.shotIds` for ordering/membership includes every shot whose (active/Pending, index) changed, not only the dragged selection; it is ordered by the resulting active array, then resulting Pending array, then removed IDs in their previous order, without duplicates. Undo and Redo use the same rule. It is a semantic affected-ID report, not a view-specific dirty-output instruction.

## Excluded parity and decisions

The legacy model has source TIFF paths, preview/filename/rename plans, `pendingDeletedShots`, `pendingBake`, `flow` source status and fingerprints, bitmap paths/active layer targets, sketch stroke data, image-layer edits, presentation mattes/dialogue overlays, project naming and timestamps, autosave/dirty state and file output/recovery policy. `ProjectV1` intentionally has none of these fields. Unknown data is rejected rather than silently discarded; **do not auto-convert or save a legacy workspace using this format**. Define migration/feature parity and side-effect ordering with the coordinator before connecting views or persistence. UI, GUI behavior, source-folder writeback, preview renderer, Photoshop/TIFF and Windows acceptance remain untested here.
