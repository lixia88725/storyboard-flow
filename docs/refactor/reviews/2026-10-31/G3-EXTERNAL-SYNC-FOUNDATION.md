## Implemented scope

- Output observation is serialized with Save, restricted to known live output bindings,
  detects changed/missing files and refuses pending output transactions. It neither adopts
  external pixels nor updates ownership. Metadata-stamp caching avoids rereading unchanged
  bytes; Save retains independent native digest checks. `localOutputChanges` includes
  text, is diagnostic, and is not the image-conflict policy.
- Pure three-way image planning combines independent layer changes against a baseline,
  retains local additions once, recognizes identical semantic images and rejects same-layer,
  ambiguous-order, uncertain-identity and alignment conflicts. Document text is outside
  its inputs. Inputs must be validated/admitted and correspondence verified by its caller.
- TIFF output rasterVersion 2 carries native `lyid` records and an XMP map to stable Flow
  layer IDs. Reads match IDs rather than positions. IDs are deterministic across rename
  and reorder; within-image collisions refuse encoding. Native duplicate/missing-map cases
  refuse guessing. Decode distinguishes portable/native/unverified correspondence;
  old positional metadata and plain images are not authority for automatic layer sync.

No refresh UI, source adoption, baseline persistence or Session history transaction is
connected yet. Read [the target design](../../EXTERNAL-TIFF-SYNC.md) for subsequent work.
The codec supports a bounded TIFF subset, not complete Photoshop or PSD compatibility.

## Independent review

A read-only reviewer found generic native-only layers still derived their `kind` from
array position, making pure reorder look like a layer edit and causing false conflicts.
The candidate uses stable `image` kind unless explicit Flow metadata supplies it. A real
TIFF decode → pure planner regression now combines native-only reorder with local pixel
editing, preserving both. Follow-up code/test-design review passed; the reviewer did not
execute tests and did not certify automatic refresh or platforms.
